大模型认知与工程概览（知识点笔记） ​

来源：ai-agents-from-zero 第 1-1 章《大模型认知与工程概览》（GitHub 仓库），原文配图与完整讲解见原站。整理于 2026-11-26。

这篇是全书的"地图页"，本文提炼其中最值得记住的知识点：大模型是什么、为什么是这个时代出现、怎么训练出来的、落地时怎么选工程方案。

一、大模型是什么 ​

  • 定义（四特征）：参数规模大、训练数据多、训练算力强、多任务上有较强通用能力。业界常把参数量 10 亿（1B）以上作为粗略分界线。

    大模型 = 用海量数据和强算力训练出来的超大规模深度神经网络模型。

  • 模型 ≠ 产品：Qwen / DeepSeek / GPT / Llama 是模型（能力本体）；ChatGPT / Claude / DeepSeek Chat 是产品（模型 + 工具 + 多模态 + 记忆 + 产品能力的完整系统）。平时说"我在用 ChatGPT"，背后工作的才是模型。
  • BERT（Google）、BART（Meta）是 NLP 时代的重要模型，但属于"大模型之前的阶段性代表"，不在今天常说的大模型主流范畴。

二、为什么大模型出现在这个时代 ​

三个条件同时成熟，缺一不可：

条件关键点
数据够多训练范式从监督学习（人工标注，成本高规模受限）转向自监督学习（预测下一个 token、恢复被遮住的部分），直接吃海量未标注文本/代码。"人先标答案"变成"机器从数据本身找学习信号"
算力够强深度学习 = 大规模矩阵运算，天然适合 GPU/TPU/NPU 并行。超大模型靠三种并行：数据并行（各卡持完整模型、处理不同数据）、张量并行（同一大矩阵按维度切开）、流水线并行（模型按层切开）
架构合理Transformer 的可扩展性：参数、数据、算力继续堆，Test Loss 还能稳定下降。大模型时代的本质是"越堆越有效"这件事终于成立了

架构演进主线 ​

阶段核心思路主要问题
RNN按顺序逐词处理，状态往后传长文本遗忘、难并行
LSTM / GRU加门控保留重要信息缓解但仍是串行
Seq2Seq编码器读输入、解码器生成中间向量是信息瓶颈
Seq2Seq + Attention解码时动态关注输入不同位置仍带 RNN 串行包袱
Transformer注意力直接建模任意 token 关系适合并行训练与规模扩展

Transformer 的三大意义：并行计算（适合 GPU 集群）、全局依赖（任意两 token 直连）、可扩展性（持续堆叠仍有效）。

Decoder-Only 与自回归生成 ​

路线典型用途直观理解
Encoder-Only表征、分类、检索、Embedding擅长"理解输入"
Encoder-Decoder翻译、摘要等边界清晰任务先读懂再生成
Decoder-Only对话、写作、代码、通用生成不断预测下一个 token

现代通用 LLM 基本是 Decoder-Only + 自回归：切 token → 按上下文预测下一个 token 的分布 → 采样 → 追加进上下文 → 继续。

统一视角（最有价值的一点）：System Prompt、用户问题、历史消息、检索结果、工具返回——最后全都变成 Decoder-Only 模型"继续预测下一个 token"的上下文。学 Prompt、RAG、工具调用、Agent，本质上都在学"如何组织上下文"。

三、三个基本量纲 ​

量纲单位易错点
参数规模B = Billion（10 亿），7B = 70 亿参数参数 = 训练学出来的权重 w + 偏置 b，不是"层数/神经元数/超参数"的统称；参数多 ≠ 一定更强
数据规模token：1B = 10 亿，1T = 1 万亿token ≠ 字数也 ≠ 单词数，是模型切词的基本单位；可用 OpenAI Tokenizer 直观体验
计算规模FLOPs：PFLOPs = 10¹⁵，EFLOPs = 10¹⁸训练不是"数据喂进去就完了"，要为海量数据 × 巨大参数付出极高计算成本

四、四类模型怎么协同（做 RAG 必懂） ​

按功能/输出形态分四类，实际项目里经常一起工作：

类型核心任务输出典型位置
LLM / 生成模型内容生成token 序列最终回答 / 决策
Embedding 嵌入模型语义编码高维向量检索前处理
Reranker 重排序模型相关性排序相关性分数检索后精排
Classifier 分类模型类别预测标签 / 概率过滤 / 路由 / 标注

一条用户提问的典型流水线（RAG 标准结构）：

  1. （可选）Classifier 判断意图
  2. Embedding 把问题转向量 → 向量库检索候选文档
  3. （可选）Reranker 精排
  4. （可选）Classifier 过滤
  5. LLM 生成最终回答

注意：建知识库和查询必须用同一类嵌入模型（同一向量空间），否则检索无效。

五、开源 vs 闭源 ​

  • 大模型四要素：训练代码（不开源）→ 训练数据集（核心竞争力，几乎不开源）→ 模型权重（"开源"通常指开放权重） → 推理代码（不一定开源）。
  • 大模型"开源"不同于传统软件开源：一般是开放权重 + 推理代码 + Tokenizer，不含完整训练代码和数据集；能否商用、能否再分发取决于许可证。
  • 商业逻辑：
    • 开源 = 技术扩散换生态影响，靠云服务、企业定制、工具链变现，形成"创新飞轮"；
    • 闭源 = 专有技术换利润，靠 API 订阅、企业方案、授权变现。
  • 混合模式成主流："开源引流，闭源变现"。例：Google 开源 Gemma + 闭源 Gemini；阿里开源通义千问家族 + 闭源企业服务；百度 2025 年开源文心 4.5 + 闭源 API。

六、模型是怎么"被教会说人话"的 ​

主流训练路径：预训练 → SFT → RLHF / RLAIF（前两步 = 后训练 Post-Training 之前的基础，SFT 起属于后训练）。

阶段学什么解决什么
预训练语言规律 + 世界知识（千亿~万亿 token 自监督"海量接龙"）能不能说话
SFT高质量标注指令数据，学"按要求回答"听不听话
RLHF / RLAIF人类/AI 偏好排序优化好不好、稳不稳、安不安全
  • 形象类比：只有预训练、没有 SFT 和对齐的模型 = "读遍天下书但没上过学的天才"——知识渊博但口无遮拦、不懂分寸。问"下雨要带什么"，它可能按概率接龙答"东西"而不是"雨伞"。
  • SFT 解决"会不会"，RLHF 解决"好不好"。RLHF 流程三步：训奖励模型（学人类偏好排序）→ 强化学习优化主模型 → KL 惩罚防止模型为追奖励漂移过头。
  • RLAIF（AI 替代人类反馈）成本更低、更易规模化，但可能继承模型自身偏差。
  • 安全边界难在多轮诱导：直球式高危请求 SFT 能拒绝，但"奶奶漏洞"（请扮演已过世的祖母念 Windows 序列号）用角色包装绕过安全边界——难点不是拒绝直球问题，而是各种包装语境下守住边界。

七、训练 vs 推理，与算力瓶颈 ​

  • 训练：前向 + 损失 + 反向传播，更新参数，目标是学到能力；推理：参数固定只做前向，使用能力。应用开发者基本只做推理，不训练基础模型。
阶段瓶颈顺序
训练显存（参数 + 梯度 + 优化器状态 + 激活值 ≈ 参数本身数倍；爆显存卸载到内存/硬盘后 I/O 变瓶颈）→ 多卡通信 → 纯算力
推理显存（参数 + KV Cache）→ 显存带宽（Decode 阶段逐 token 生成，每出一个 token 都要加载整个模型和 KV Cache，计算单元大部分时间在等数据）→ 多卡通信 → 算力（Prefill 阶段计算密集）

金句：训练更像"又大又重的长期工程"，推理更像"高并发、低延迟的持续服务问题"。

硬件速记：

  • CPU：少量强 ALU，通用任务串行；GPU：大量简单单元并行（现代 GPU 加 Tensor Core 矩阵单元适配深度学习）；NPU：砍掉通用性（如 FP64）专攻神经网络，高性能低功耗；TPU：谷歌的专用芯片（本质也是 NPU），Gemini 在 TPU 上训练。
  • 显存（VRAM）= GPU 的工作空间，模型参数、激活值、KV Cache 都占显存——所以显存是大模型场景最关键的资源。
  • GPU 市场英伟达一家独大（V100 → A100 → H100/H800 → H200 → B200），国内华为昇腾、摩尔线程、寒武纪在追赶。

八、幻觉：只能缓解，无法根除 ​

  • 定义：生成内容看起来合理流畅，但实际上错误、不可验证或与事实不符——危险在于"说得很像真的"。
  • 产生原因：训练语料缺相关信息、提示词歧义、上下文不足、模型被要求"必须回答"、超出知识/时间边界。
  • 常见类型：事实性幻觉（编论文/法条/接口）、源引用幻觉（编 DOI）、逻辑幻觉（推理自洽但前提错）、过度自信幻觉（错误但语气 100% 确定）、工具/代码幻觉（编不存在的 API 和参数）。
  • 为什么无法彻底消除（系统性原因）：
    1. LLM 是生成模型不是知识库；
    2. 训练数据本身有噪声与冲突；
    3. RLHF 强化的是"有用回答"而非"拒答"；
    4. 生成任务天然追求完整性而非保守性。
  • 行业共识：幻觉只能控制、缓解、检测——这正是 Prompt、RAG、微调、工作流、工具调用这套工程方案存在的根本原因。

九、工程落地五大模块与选型顺序 ​

应用开发的五个模块，按"成本从低到高"依次考虑：

模块什么时候用
提示词工程最先尝试，最轻最便宜：改写任务描述、加示例、规定输出格式
RAG模型缺知识、缺资料、缺最新信息时
微调不是缺知识，而是行为不稳定、风格不统一、格式不听话时
续训对某领域语言分布和知识结构系统性缺失时
智能体开发需要多步规划、工具调用、环境交互、流程执行时

关键认知：应用开发不是"把模型接上"，而是把模型、知识、工具、流程组织成一个可靠系统。例：电商问数不是直接让模型写 SQL，而是先围绕元数据建知识库，再做召回、筛选、生成、校验和执行。

十、三个值得记住的认知纠偏 ​

  1. "模型刚回答过，所以它学会了"是错的——推理只是在当前上下文使用已有参数，不会把知识写进模型。想长期改变能力要靠训练/微调/续训；应用层想"记住"，靠历史消息、数据库、RAG 或记忆模块。
  2. 企业文档问答的选型：大多数情况先 Prompt + RAG（Prompt 说清规则，RAG 补资料），微调/续训成本高、仅在行为稳定性或领域底层能力确实不足时考虑，Agent 留给"查系统、调工具、多步执行"的场景。
  3. AIGC vs AGI：AIGC 的 G 是 Generated（生成，已广泛落地），AGI 的 G 是 General（通用，尚未实现）；通向 AGI 的两条路径 = 提升基础模型通用能力 + 用 Agent 设计做能力组织调度（目标分解、长期规划、工具使用、环境交互）。
