Vue ​

Vue 是目前国内用得最多的前端框架，核心思路一句话：数据交给 Vue 管，数据一变页面自动跟着变，不用手写 DOM 操作。对后端来说它是搭管理后台最快的路子——官方脚手架建项目，配上 Element Plus 这套现成的 UI 组件库，表格、表单、弹窗基本不用自己写样式。

这篇走一个真实后台项目的完整流程：建项目、认识目录、路由布局、封装 axios 调接口、打包部署。做完手上就有一个能改吧改吧直接用的管理后台骨架。前置条件：装好 Node.js，步骤在 Node.JS 安装。

建项目 ​

bash
npm create vue@latest
1

这是 Vue 官方脚手架 create-vue，会连着问一串问题。项目名填 vue-admin，TypeScript 选 Yes（企业项目现在默认都是 TS，后端对类型不陌生），Router 选 Yes，剩下全部回车 No。

然后装依赖、启动：

bash
cd vue-admin
npm install
npm run dev

浏览器打开 http://localhost:5173/ 看到欢迎页就跑通了。改代码保存后页面自动刷新，这是 Vite 的热更新，后面写代码基本不用手动刷浏览器。

el-menu 上的 router 属性是关键：开启后点菜单项会按 index 的值直接跳路由，不用自己写跳转逻辑。:default-active 绑当前路径，刷新页面菜单高亮也不丢。另外那个 :deep() 是 scoped 样式的一个实战坑——<style scoped> 只管当前组件写的元素，想选中 Element Plus 内部生成的节点要用 :deep() 穿透，记住这个写法能少绕很多弯路。

调后端接口 ​

前端的分工很清楚：页面和交互归前端，数据全部来自后端接口。前端发请求用的库基本是 axios：

bash
npm i axios
1

别在页面里直接 axios.get，先在 src/utils/request.ts（utils 目录自己建）封装一个，token、报错统一处理，这是所有正经项目的标准做法：

ts
import axios from 'axios'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE,
  timeout: 10000
})

// 请求拦截器：每个请求自动带上 token
request.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// 响应拦截器：直接返回后端的数据体，顺便统一处理登录过期
request.interceptors.response.use(
  res => res.data,
  err => {
    if (err.response?.status === 401) {
      localStorage.removeItem('token')
      location.href = '/login'
    }
    return Promise.reject(err)
  }
)

export default request

开发时的跨域问题用 Vite 的代理解决，vite.config.ts 改成：

ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:5000', // 换成你后端的地址
        changeOrigin: true
      }
    }
  }
})

原理：页面跑在 5173，后端跑在 5000，端口不同浏览器会拦跨域请求。走代理后浏览器请求的是同源的 5173/api/users，Vite 在中间转发给后端，浏览器根本感知不到跨域。上线之后同样的事由 nginx 来做，所以环境变量里写 /api 这种相对路径，开发和生产两头通用。

views/UsersView.vue 换成：

vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'
import request from '../utils/request'

interface User {
  id: number
  name: string
  email: string
}

const list = ref<User[]>([])
const loading = ref(false)

async function fetchUsers() {
  loading.value = true
  const res = await request.get('/users')
  list.value = res.data
  loading.value = false
}

onMounted(fetchUsers)
</script>

<template>
  <el-card>
    <el-table :data="list" v-loading="loading">
      <el-table-column prop="id" label="ID" width="80" />
      <el-table-column prop="name" label="姓名" />
      <el-table-column prop="email" label="邮箱" />
    </el-table>
  </el-card>
</template>

几个要点：onMounted 是组件挂载完的钩子，拉数据的调用放这；ref 包住接口数据，赋值时 list.value = ...，表格自动更新；响应拦截器已经剥掉 axios 那层，res 拿到的直接是后端返回体，res.data 就是上面 JSON 里的 data 字段。表格、加载动画全是 el-table 一个标签的事，这就是上组件库的好处。

写增删改查就是把 request.get 换成 request.post / request.put / request.delete，要传的数据作为第二个参数，套路完全一样。

打包部署 ​

再建一个 .env.production（build 时自动启用）：

text
VITE_API_BASE=/api
1

生产环境还是 /api，靠 nginx 把 /api 转发给后端。然后构建：

bash
npm run build
1

产物在 dist/，一堆静态文件。nginx 配置：

nginx
server {
    listen 80;
    server_name your.domain.com;

    # 前端静态文件
    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 接口转发给后端
    location /api/ {
        proxy_pass http://localhost:5000;
    }
}

try_files 那行别删：路由用的是 history 模式，URL 长得像 /users 但服务器上并没有这个文件，刷新时 nginx 找不到会 404，这行的意思是找不到就回退到 index.html，让前端路由自己接管。

dockerfile
