三、面向对象 ​

本篇接续《.NET基础拾遗（1）》的第一、二章，继续以 Q/A 形式整理面向对象的核心考点。要点归纳自 Edison Zhou 的「.NET基础知识快速通关」系列第 3、6、9 篇，代码示例做了精简重写。

3.1 .NET 中的类可以多继承吗？ ​

不能。C# 只支持单继承（一个父类），但支持实现多个接口，Java 同样如此。

多继承看似更贴合现实建模（例如"带文本的矩形"既能画矩形又能输入文本），但 C++ 的实践暴露了菱形（砖石）继承问题：最终子类会从两条继承路径上拿到两份"源自同一个基类"的成员，编译器无法确定该用哪一份。.NET 设计组因此彻底放弃了类多继承。

取而代之的思路是：接口只定规范（做什么），实现类负责细节（怎么做）。接口不做实际工作，抽象性和灵活性反而更好，因此承担了面向对象中主要的抽象职责。

3.2 重写、重载和隐藏有什么区别？ ​

这三个概念是设计可扩展类型的基础，最容易混淆的是重写与隐藏。

（1）重写（override）与隐藏（new）

  • 重写：子类用 override 重新实现基类的 virtual 方法，运行时按对象的实际类型分派。
  • 隐藏：子类用 new 重新实现基类方法，运行时按引用的静态类型分派。
public class BaseClass
{
    public virtual string GetString() => "我是基类";
}
public class OverrideBase : BaseClass
{
    public override string GetString() => "我重写了基类";
}
public class NewBase : BaseClass
{
    public new string GetString() => "我隐藏了基类";
}

BaseClass obc = new OverrideBase();
BaseClass nbc = new NewBase();
Console.WriteLine(obc.GetString()); // 我重写了基类 —— 按对象实际类型
Console.WriteLine(nbc.GetString()); // 我是基类   —— 按引用类型，隐藏失效

（2）重载（overload）

同名方法具有不同的参数列表（参数个数、类型或顺序），与返回值无关。构造方法、ToString() 是最常见的重载应用，编译期即可确定调用哪个版本。

PS：重载是编译期多态（静态绑定），重写是运行期多态（动态绑定），这是面试里区分二者的关键。

3.3 为什么构造方法中不能调用虚方法？ ​

这是 C# 里一个隐蔽但危险的坑。CLR 调用虚方法时永远按对象实际类型分派，而构造顺序是：

执行成员变量初始化表达式 → 执行父类构造方法 → 执行自己的构造方法
1

也就是说，当基类构造方法执行时，子类对象已经"是"子类类型了，但子类的构造方法和成员初始化还没跑完。此时基类构造方法里调用虚方法，会分派到子类的重写版本，而该版本若访问子类尚未初始化的成员，就会抛出 NullReferenceException。

public class A
{
    public A() { Console.WriteLine(ToString()); } // 危险：调用虚方法
    public override string ToString() => "A";
}
public class B : A
{
    private Ref my2;                              // 此时还是 null
    public B() { my2 = new Ref(); }
    public override string ToString() => my2.str; // 空引用异常
}

实践准则：永远不要在非叶子类（可被继承的类）的构造方法中调用虚方法。同理，设计可被继承的类型还要额外考虑序列化、ICloneable 等接口会被强制传递给所有子类的问题。

3.4 如何声明一个不能被继承的类？ ​

用 sealed 关键字，编译期即保证不可继承：

public sealed class OrderService { }
1

更重要的结论是工程上的：没有派生需求的类型都应该显式加 sealed。这既避免继承带来的不可预期问题，也让 JIT 有机会做去虚化优化。判断依据不是"以后可能要不要扩展"，而是"当前是否设计过被继承"。

3.5 小结：三条可落地的编码规则 ​

场景做法
需要多态基类 virtual + 子类 override，不要用 new 隐藏
编写可被继承的基类构造方法中不调用虚方法；否则加 sealed
需要组合多种能力用多个接口，不要试图多继承

四、集合与泛型 ​

4.1 int[] 是值类型还是引用类型？ ​

数组本身一律是引用类型，无论元素是值类型还是引用类型。所有数组都继承自 System.Array，而 System.Array 继承自 System.Object，内存分配在托管堆上。

区别只在元素存储方式：

  • int[]：值直接包含在数组内存里（内联），元素已是真实数据；
  • object[]：数组里存的是引用，指向堆中各个实例对象。

另外，CLR 会检查每一次数组访问，越界一律抛 IndexOutOfRangeException——这是数组相比非托管数组更安全的地方，也是它稍有性能开销的原因。

4.2 数组之间如何转换？ ​

类型转换要守两条规则：

  1. 值类型元素的数组不能隐式转换成任何其他类型；
  2. 两个数组能互相转换的前提是维数相同。
string[] sz = { "a", "b", "c" };
object[] oz = sz;          // 可以：引用类型数组，协变
int[] sz2 = { 1, 2, 3 };
// object[] oz2 = sz2;    // 编译失败：值类型数组不协变
string[,] sz3 = { { "a", "b" } };
// object[] oz3 = sz3;    // 编译失败：维数不同

4.3 泛型的基本原理是什么？ ​

泛型（.NET 2.0 引入）类似 C++ 模板，核心价值有两个：设计通用类型、避免容器操作的装箱拆箱（呼应第一篇 1.3 节）。

public static class SortHelper<T> where T : IComparable
{
    public static void BubbleSort(T[] array)
    {
        for (int i = 0; i <= array.Length - 2; i++)
            for (int j = array.Length - 1; j >= 1; j--)
                if (array[j].CompareTo(array[j - 1]) < 0)
                {
                    T temp = array[j];
                    array[j] = array[j - 1];
                    array[j - 1] = temp;
                }
    }
}

两个容易考到的概念：

  • 开放式类型：只声明了泛型参数、尚未指定实参的类型。.NET 规定它不能实例化（CLR 无法确定该分配多少内存）。
  • 封闭类型：为开放类型指定具体实参后生成的新类型。它与开放类型在类结构图上处于同一层次，彼此没有继承关系。

编码规范：泛型参数名一律以 T 开头，接口名一律以 I 开头。

实践上应优先使用 System.Collections.Generic 下的 List<T>、Dictionary<TKey,TValue>、LinkedList<T> 以及 System.Array 的静态泛型方法，而不是 ArrayList 这类基于 object 的旧容器。

4.4 泛型的主要约束和次要约束是什么？ ​

没有约束时，编译器对实参一无所知，泛型体内能做的操作极其有限。约束就是让编译器能对实参做出类型保证。

（1）主要约束：至多一个，可以是具体引用类型、class 或 struct。

public class ClassT1<T> where T : Exception   // 实参必须是 Exception 或其派生类
{
    public string Describe(T ex) => ex.Source; // 约束保证成员可用
}
public class ClassT2<T> where T : class        // 引用类型，可置 null
{
    private T value;
    public void Clear() => value = null;
}
public class ClassT3<T> where T : struct       // 值类型，不会 NullReference
{
    private T value;
    public override string ToString() => value.ToString();
}

五、委托与事件 ​

5.1 事件如何使用？ ​

事件的定义是：使对象或类能够提供通知的成员。客户端提供事件处理程序（回调）来响应通知，本质上是观察者模式的语言级支持。标准实现分四步：

// ① 定义事件参数：继承 EventArgs
public class ConsoleEventArgs : EventArgs
{
    public string Message { get; }
    public ConsoleEventArgs(string message) => Message = message;
}

// ② 定义发布者：声明事件 + 受保护的触发方法
public class ConsoleManager
{
    public event EventHandler<ConsoleEventArgs> ConsoleEvent;

    public void ConsoleOutput(string message)
    {
        SendConsoleEvent(new ConsoleEventArgs(message));
        Console.WriteLine(message);
    }

    protected virtual void SendConsoleEvent(ConsoleEventArgs args)
    {
        // 用临时变量接收，避免多线程下订阅列表变化导致空引用
        var temp = ConsoleEvent;
        temp?.Invoke(this, args);
    }
}

// ③ 订阅者：+= 绑定处理方法
public class Log
{
    public Log(ConsoleManager cm) => cm.ConsoleEvent += WriteLog;
    private void WriteLog(object sender, ConsoleEventArgs e)
        => File.AppendAllText("log.txt", $"{DateTime.Now:yyyy-MM-dd HH:mm:ss}|{e.Message}\n");
}

// ④ 使用
var cm = new ConsoleManager();
var log = new Log(cm);
cm.ConsoleOutput("测试事件");

EventHandler<TEventArgs> 是框架提供的标准委托，签名固定为 void (object sender, TEventArgs e)：第一个参数是事件源，第二个是事件参数，无返回值。

5.2 事件和委托是什么关系？ ​

委托的本质是一个类型，事件的本质是一个特殊委托类型的实例。

编译 public event EventHandler<ConsoleEventArgs> ConsoleEvent; 时，C# 编译器会：

  1. 为类型添加一个 EventHandler<ConsoleEventArgs> 私有委托字段；
  2. 生成一对 add_ConsoleEvent / remove_ConsoleEvent 访问器；
  3. 访问器内部调用 Delegate.Combine / Delegate.Remove 增减委托链上的方法。

所以 += 就是把处理方法加入委托链，订阅的本质是委托链操作。这也解释了为什么事件在类外只能 +=/-=，不能直接 = 赋值或调用——编译器把字段私有化，只暴露 add/remove，从而避免外部订阅者误清空别人的订阅。

5.3 一个类型有很多事件时怎么设计？ ​

如果为每个事件都声明一个委托字段，即使一个都没被订阅，对象也要为所有字段付内存成本（WinForms 控件动辄几十个事件）。框架的解法是 EventHandlerList：把所有委托链存进一个容器，用静态 object 作为 key 索引，显式实现 add/remove。

public partial class MultiEventClass
{
    private readonly EventHandlerList events = new EventHandlerList();
    private static readonly object Event1Key = new object();

    public event EventHandler Event1
    {
        [MethodImpl(MethodImplOptions.Synchronized)]
        add => events.AddHandler(Event1Key, value);
        [MethodImpl(MethodImplOptions.Synchronized)]
        remove => events.RemoveHandler(Event1Key, value);
    }

    protected virtual void OnEvent1(EventArgs e)
        => (events[Event1Key] as EventHandler)?.Invoke(this, e);
}

要点：

  • 每个事件一套「委托原型 + 静态 Key + add/remove + OnXXX 触发方法」；
  • EventHandlerList 自身不做线程同步，需要 [MethodImpl(MethodImplOptions.Synchronized)]；
  • 设计目的不是减少代码量，而是减少多事件对象的体积，且订阅方完全感知不到内部改动。

5.4 经典场景：猫叫 → 老鼠跑、主人醒 ​

观察者模式的教科书例子，事件源是猫，订阅者是老鼠和主人：

public class Cat
{
    public event EventHandler CatCryEvent;
    public void CatCry() => CatCryEvent?.Invoke(this, EventArgs.Empty);
}
public class Mouse
{
    public Mouse(Cat cat) => cat.CatCryEvent += (s, e) => Console.WriteLine("老鼠逃走了");
}
public class Master
{
    public Master(Cat cat) => cat.CatCryEvent += (s, e) => Console.WriteLine("主人醒了");
}

var cat = new Cat();
_ = new Mouse(cat);
_ = new Master(cat);
cat.CatCry(); // 一次触发，两个订阅者各自反应，彼此不依赖
